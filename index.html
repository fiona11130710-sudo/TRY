行人穿越道（斑馬線）AI 辨識與靜態道路硬體危險度評估系統

針對單張街景或行車記錄器影像，於瀏覽器地端執行單類別物件偵測模型，結合原圖像素灰階統計與幾何視角演算，自動化產出標線老化、能見度及視線幾何風險分析報告。

前往實作測試區

核心 AI 辨識能力

結合輕量化 YOLO26n 模型與原生 Canvas 像素運算，專注於行人穿越道硬體狀態檢測

斑馬線物件偵測

採用單類別訓練之 YOLO26n 模型（crosswalk），透過 Letterbox 等比例縮放前處理與非極大值抑制（NMS），精準框選影像中的斑馬線區域。

標線像素對比與能見度分析

直接回溯原始解析度影像裁切目標框，轉換為標準亮度灰階（0.299R + 0.587G + 0.114B），計算 P90−P10 對比度與平均亮度，量化褪色及光線異常。

幾何位置與視野評估

依據偵測框與影像邊界之相對比例，判定標線是否遭畫面裁切遮擋，並針對駕駛視角估算車頭視線盲區距離與空間壓迫占比。

自動化風險分級報告

將五大硬體與幾何指標轉換為 0～7 分量化評分，自動劃分低、中、高風險等級，並列舉指標實測數據與對應之改善建議。

視覺化標註圖例： 綠色邊框（#00FF00）：代表模型偵測到的斑馬線（crosswalk）範圍 信心 %：代表模型判定該區域為斑馬線的信心程度（僅供參考，不納入風險計分）

靜態危險度評估標準

系統選取信心度最高之斑馬線框（原圖座標）進行以下五項指標計分，總分範圍 0～7 分

註：下列數值門檻為教學示範暫定值，可於程式碼頂端常數區調整
類別 評估指標 計算方式與暫定門檻 配分
A. 標線狀態
（主要指標）		 1. 標線清晰度 框內灰階第 90 百分位減第 10 百分位（P90 − P10）：
• ≥ 80 → 0 分（對比鮮明）
• 50 ～ 80 → 1 分（輕度褪色或磨損）
• < 50 → 2 分（白線與路面嚴重缺乏對比） 		0～2 分
2. 框內能見度 框內像素平均灰階值：
• 70 ～ 200 → 0 分（光線適中）
• 40 ～ 70 或 200 ～ 230 → 1 分（偏暗或偏亮）
• < 40 或 > 230 → 2 分（嚴重過暗或強光過曝） 		0～2 分
3. 完整度 偵測框任一側邊距影像邊界小於影像寬/高之 2%：
• 未貼邊 → 0 分
• 貼近邊緣 → 1 分（標線可能遭畫面裁切或遮擋） 		0～1 分
B. 位置與大小
（輔助指標，限駕駛視角）		 4. 視線盲區 底邊距離比 = (圖高 − (y + h)) / 圖高：
• ≥ 0.18 → 0 分
• < 0.18 → 1 分（過於貼近車頭下方視線盲區） 		0～1 分
5. 空間壓迫 高度佔比 = h / 圖高：
• ≤ 0.25 → 0 分
• > 0.25 → 1 分（標線在畫面縱向佔比過大、距離過近） 		0～1 分
總分風險分級對照
  • 0 ～ 1 分低風險 標線對比清晰、可視狀態良好
  • 2 ～ 3 分中風險 局部磨損、光線不佳或視角偏近
  • 4 ～ 7 分高風險 多項硬體/能見度/幾何條件異常
  • 未檢出無法評估 信心度皆低於 0.40 門檻
計分原則說明：模型的「信心分數（%）」僅代表辨識把握度，可能受鏡頭模糊或角度影響，因此不納入危險度計分；所有風險分數皆由原圖像素與幾何位置客觀計算。

交通風險與辨識場景

說明各類靜態路面與拍攝視角狀況下，系統的指標反應與判定邏輯

風險類別 辨識場景說明 偵測方式與系統判定結果
標線褪色或磨損 長期車輛輾壓導致白漆剝落、灰黑混雜，標線與柏油路面反差不明顯。 計算框內灰階 P90 − P10 差值低於 80（或 50），清晰度指標計 1～2 分，提示標線對比不足。
光線過暗或過曝 夜間無路燈照明、隧道出入口逆光、積水反光或正午強光直射導致細節遺失。 計算框內平均灰階低於 70 或高於 200，能見度指標計 1～2 分，提示環境光線不利辨識。
斑馬線被切掉或遮住 拍攝角度偏斜、距離過近或受前車遮擋，使標線延伸至影像最邊緣遭截斷。 檢測框四邊任一側距離圖邊小於 2% 尺寸，完整度指標計 1 分，提醒標線範圍不完整。
視線盲區 行車記錄器視角下，斑馬線底緣已極度貼近畫面底部（車頭引擎蓋或 A 柱前緣盲區）。 底邊距離比 (圖高 − (y+h)) / 圖高 < 0.18，視線盲區指標計 1 分。
空間壓迫 車輛距離行人穿越道過近，或鏡頭俯角過大導致標線在畫面中佔據過大垂直高度。 高度佔比 h / 圖高 > 0.25，空間壓迫指標計 1 分。
未偵測到斑馬線 無斑馬線之一般路段、標線已完全磨滅至無法辨識，或非街景影像。 無候選框通過 0.40 信心門檻，風險等級顯示「無法評估（灰色）」。
目前尚未支援之功能範疇：本系統專注於單張靜態影像之「斑馬線硬體狀態」檢測，尚未包含紅綠燈號誌狀態辨識、行人/車輛物件偵測、安全帽配戴檢測，以及未禮讓行人、違規停車、逆向行駛等動態交通行為分析。

模型訓練工作流與架構延伸

從資料集建置到前端邊緣推論之完整實作管線

STEP 1 · 資料標註
Roboflow 標註與增強

蒐集多時段道路街景影像，標註單一類別 crosswalk 邊界框並進行亮度與翻轉資料增強。

STEP 2 · 模型訓練
Google Colab 訓練

使用 Ultralytics 框架訓練輕量化 YOLO26n 模型（輸入尺寸 640×640），兼顧推論速度與定位精度。

STEP 3 · 格式匯出
匯出 ONNX 格式

將權重匯出為跨平台標準 best.onnx（約 9.8MB，輸出張量 [1, 5, 8400]），部署於靜態網頁目錄。

STEP 4 · 前端推論與調參
瀏覽器端推論與常數校正

透過 ONNX Runtime Web 執行推論；開發者可直接修改 <script> 最上方的門檻常數以校正場域標準。

系統核心技術特色

純地端推論（Zero-Backend）

完全無需後端 GPU 伺服器，透過 WebAssembly（WASM）於使用者裝置本地端載入 ./best.onnx，上傳照片不會傳送至任何外部主機，兼具隱私安全與低部署成本。

YOLO 空間標定與 Letterbox 還原

前處理採用灰邊填充（RGB 114）維持原圖長寬比不變形；後處理解析屬性優先排列之 8400 個候選網格，執行 IoU 0.45 非極大值抑制並精確還原原圖座標。

像素分析與評分決策引擎

利用離屏 Canvas 擷取原始未壓縮影像 ROI 像素陣列，進行百分位數分布統計與邊界距離演算，將視覺偵測結果轉化為可解釋之量化評估報告。
